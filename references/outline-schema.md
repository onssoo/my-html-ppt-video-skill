# `大纲.md` —— 制作 PPT 的剧本（Gate ① 的唯一真源）

> **本文从属于 owner 的《商务演示文稿制作规范》（`business-deck-spec.md`）。**
> 格式、密度、字号一律以规范为准；本文只写「脚本实际认哪些标记」与落地细节，冲突时以规范为准。
>
> 本文与实现（`ppt2video.py` 的 `parse_outline_md` / `outline_preflight`）**逐字对齐**；
> 小样本见 `tests/fixture-大纲.md`——**改格式先改它**。

流程：**读源文档 → 构思 → 写 `大纲.md` → Gate ① 审过 → 做 slides → 解说词 → 出片。**

`大纲.md` 由人和模型共写，脚本只解析下面几个标记。**改大纲不需要改代码。**

## 文件格式

```markdown
# <项目名> · 大纲

- 受众：拟合作投资人
- 用途：投资人参考 / 配音讲解视频
- 目标时长：14 分钟
- 主线：一句话说清这份材料要让受众记住或决定什么
- 素材：原文.md

## P1 封面标题也写结论
- 版式：封面：kicker + 主标题 + 副标题 + 标签行（模板 cover.html）
- 信息点（1）：
  1. 主标题：…
- 时长：12 秒
- 讲述要点（3–5 条，每条注明出处）：
  1. …（源文档 一、（二））
- 舍弃：源文档里有、这一页不用的内容

## P2 内容页的标题必须是结论
- 版式：KPI 条(3) + 结论框（模板 kpi-grid.html）
- 信息点（8）：
  1. KPI：份额 92%
  2. …
- 时长：45 秒
- 讲述要点（3–5 条，每条注明出处）：
  1. 这个数字的来历或口径（源文档 二、（一））
```

### 脚本认的标记

| 标记 | 用途 |
|---|---|
| `## P<n> <标题>` | **页边界 + 页标题**（`P` 后是页号）|
| `- 版式：…` | 这一页用什么组件组合；建议括注模板名（`（模板 kpi-grid.html）`），做 slides 时对号 |
| `- 信息点（N）：` | **N 必须等于下面条目数**（脚本会核）；条目即画面上要放的结论与证据 |
| `- 时长：<秒> 秒` | 这一页解说词的**目标秒数（绝对秒，不是权重）** |
| `- 讲述要点（…）：` | 讲的时候说、但不写在画面上的内容；进 deck 的 `<div class="notes">`，也是解说词素材 |
| `- 舍弃：…` | 可选。这一页舍弃了什么，留痕便于回溯 |

文件开头的 `- 受众 / 用途 / 目标时长 / 主线 / 素材` 会被读出来做预检与预算。

## 硬规则（都来自规范）

1. **页标题写结论，不写话题**，≤30 字、单行：`海外企业合计约 77%` ✔ ／ `竞争格局` ✘（规范 §一 第 14 行）。
2. **信息点计数**（规范 §二 第 40 行）：1 条要点 / 1 个 KPI / 1 个结论框 / 表格 1 行（表头不算）/ 1 张图 各算 1 个；
   一条要点超过 2 行算 2 个（条目末尾注明「（占 2 行）」）。
3. **内容页 6–10 个信息点**，超过 10 必须拆页；**封面、目录、章节页、结尾页不受此限**（规范 §二 第 41 行）。
   同理，这些非内容页的**解说词字数下限**也只按自己的 `- 时长` 推算，不套内容页的全局下限。
4. **每条要点 ≤2 行**；放不下时按「精简措辞 → 换版式 → 拆页」，**禁止缩字号**（规范 §二 第 44 行、§三 第 62 行）。
5. **讲述要点 3–5 条，是对画面的补充**（原因、条件、含义、数字来历），**不能复述画面文字**（规范 §一 第 33 行）。
6. **含数字的要点要注明出处**——出处写在**幕后的讲述要点**里（供解说词溯源），**不写进画面**。
   写法随意，源文档的章节号、表号都行：`（§3.1）`、`（源文档 二、（二））`、`（表 11）`。
7. **数字逐字来自源文档**，不许换算或推算。
8. **默认不加免责、不加声明、不写材料性质**；owner 明确要求时才用 `--disclaimer`。
9. `- 时长` 是解说词的**规划值**：成片多长由解说词详略决定。同一页想讲久一点就写大一点，
   **不必为凑总时长删页**（删页是内容决策，不是时长决策）。

## Gate ① 预检（`outline 大纲.md`）

```bash
$PY ppt2video.py outline 大纲.md          # → 大纲-审核报告.md（ERROR 必须清零）
```

| 检查 | 级别 | 依据 |
|---|---|---|
| 页号连续、开头五项齐全、每页有「版式」与「时长」 | ERROR / WARN | — |
| `信息点（N）` 与实际条数不符 | ERROR | — |
| 内容页信息点不在 6–10 | ERROR（>10）/ WARN | 规范 §二 第 41 行 |
| 标题 >30 字 | WARN | 规范 §一 第 14 行 |
| 讲述要点不在 3–5 条 | WARN | 规范 §一 第 26 行 |
| **含数字的要点没注明出处**（纯解释性、无数字的不查） | WARN | 规范 §一 第 26 行 |
| **表格 >4 列** | ERROR | 规范 §二 第 43 行、§三 第 61 行 |
| **表格行数超出画布** | ERROR/WARN | 几何推算：可用 665px ÷ 行高 71px → 有图注 7 行 / 无图注 8 行 |
| 单个格 >12 字、图注合计 >60 字 | WARN | 规范 §三 第 61 行（做 slides 时会被精简）|
| KPI 条 >4 个 | WARN | 规范 §三 第 61 行 |
| 出现免责/声明类内容 | ERROR | owner 要求默认关闭 |
| 数字在源文档里查不到 | WARN | 数字溯源 |

> 这套自动检查**不是规范条款**，是脚本加的便利校验（规范只定义格式与密度）。
> 「时长合计 ≈ 目标时长」只在报告里做**规划参考**显示，**不用来反过来砍页数**。

## 与 deck 的接口

`deck-skeleton` 把每一页落成 deck 骨架（依据规范 §六 第 84 行）：

```bash
$PY ppt2video.py deck-skeleton 大纲.md      # → deck-骨架.html
```

- 页标题 → `<section class="slide" data-title="…">`（英文引号会被转义）
- `- 时长：45 秒` → `data-sec="45"`（**绝对秒**，与规范 §六 一致）
- 讲述要点（含出处）→ `<div class="notes">…</div>`（**隐藏**，画面上不出现）

**画面上永远不写来源**：出处只活在 `.notes` 里。
